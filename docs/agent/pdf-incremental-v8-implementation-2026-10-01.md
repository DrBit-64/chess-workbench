# v8 跨任务增量提取实施与验收（2026-10-01）

当前网站从 v8 独立提取结果创建「连续提取」文档后，下一次「继续增量提取」登记 `pdf-extraction:v9` 任务。v9 是 **v8 来源关系管线的增量形态**，并非回退到 v7 语义事件管线；v5/v7 历史任务仍保留原行为。网页仍使用现有连续文档卡片、追加页段、合并审核入口，无需新技术表单。

## 前驱输入与输出所有权

1. 文档基线是已批准的人工审核修订（若存在），否则是原始规范化候选。批准时的哈希、不可变路径进入文档第一版；之后每次追加都绑定上一版的精确哈希。已创建的文档不追随后来对旧审核任务的编辑。
2. 程序从前段已保存的 `ocr_fragment` 读出最近一局的连续原文、颜色/粗细样式和来源位置，作为 **只读前驱**。过长时只截去最早的连续页，保留最新局面的完整合法锚点目录。追加页段本身是唯一的 `owned_span_refs`；前驱文字只能用于理解，不能重复生成棋步或正文。
3. 程序从规范化 CCEF 构造合法 `ContinuationAnchor`；模型收到仍在上一来源页活动的棋局锚点、局面 FEN、节点路径、回合、主线身份，以及原文片段哈希/字符偏移。模型为每个续接入口返回 `games[].kind="continuation"`、`seed_ref="anchor-N"`，其第一段关系从 `entry=root` 开始且仅引用追加页的棋步 token。真正的新棋局继续返回 `kind="game"`、`seed_ref="start"` 或来源图示。
4. 本地关系编译器只接受目录中的锚点，用其 FEN 验证新棋步；续接绑定包含前驱规范化包哈希和锚点 ID。合并器按显式绑定接入原棋局，确定性地重命名跨页撞名的局部条目 ID，保留前段节点与证据。错误仍是局部待审内容，不依靠扫描所有合法 FEN 猜挂接。

这使任务 A 包含完整棋局 1 和棋局 2 的开头、任务 B 接棋局 2 后半时，合并结果中只有一局棋局 2；任务 B 同页后半若开始棋局 3，则棋局 3 独立出现。跨多个追加任务时，下一次以最新合并版本为前驱，并从所有已提交页段读所需的来源原文。

## 当前边界

- 新建连续文档时只采纳**当时已批准**的人工修订；未批准的草稿不会作为前驱，创建后再修改旧审核也不会自动改写已存在的文档。若要使用后来的修订，应从该修订重新创建连续文档。
- 本轮验证了完整来源与精确锚点对局内续接、页中换局的有效性；不等于旧 R5/P6 六书 18 窗口全量质量验收。注释挂接仍按用户决定不作为当前阻塞。
- 三本书中的这些增量切点在离线语义层通过，且隔离数据库闭环通过；尚未代用户在其浏览器里发起真实追加任务并人工审核页面。真实网页操作仍可暴露 UI 交互问题，需按实际结果处理。
