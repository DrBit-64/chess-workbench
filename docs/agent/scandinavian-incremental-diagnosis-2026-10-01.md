## 2. 大批棋步成为正文的完整因果链

### 2.1 前文已提供，跨任务第一次续接成功

第一个窗口正确声明 game2-cont，以 anchor-144 为外部起点。这个锚点明确指向前段 sequence2 的 move142，即 p47 的 7...Qe7，FEN 为白方第 8 步待走。输出顺利从 p48 的 8.exf7+ 续到 p50 的 14...Qe6+?，包括其间变化。

### 2.4 本地容错使可恢复的棋谱结构消失于审核界面

追加在失效节点降级前共有 141 个棋步候选，57 个位于错误入口下。localize_invalid_relation_subtrees 删除其 move 事件和父子映射，只为第一个 Kd1 保留 unresolved。随后 compile_relations 把没被棋步消费的全部原文复制为 prose。

于是“1 个入口问题，影响 57 个候选”变成了“1 个待审词 + 大量普通正文”。这不是模型把 57 个候选全判成注释，而是应用层的降级行为。该做法违背 ADR 0022 所述不能将未解决棋谱伪装为普通完整正文的目标。

score_candidate 只检查来源片段是否在任一 item.evidence 出现。即使整段棋谱仅作为 prose 保存，也算 represented。因此当前报告为 87/87 片段覆盖、0 非法节点、1 待审，不能表达丢谱规模；人工修掉唯一待审词后，余下候选仍不成为显式阻塞组。

## 4. 正文碎片与红圈乱码的原因

两次候选分别有：

| 页段 | 顶层 prose | 谱内 annotation | 仅数字/标点的文本项 |
| --- | ---: | ---: | ---: |
| p41–47 | 124 | 40 | 71 |
| p48–52 | 97 | 20 | 41 |

最后一列按字符形态统计，包含比分等少量有意义项；大量内容是脱离 SAN 后的回合号。所有这些 prose/annotation 都仅有一个来源 evidence，没有利用多来源段落能力。

四个已证实的具体问题：

1. **物理行当成语义段落。** PDFium 保存的是 text-lines-v1。p50 “Every black move ... White is” 与下一行 “never given a moment’s rest to develop.” 字符完整，但两个 source span 被编成两个顶层 prose，前端各加页码/按钮和间距。
2. **仅减掉 SAN，留下回合号。** p50 “11 ... Rxe3!!” 去掉 Rxe3!! 后变为正文 “11 ...”；“12 Kxe3 Bc5” 变为 “12”。数字本应属于棋谱表达的范围。
3. **抽空混合段落破坏语法。** p44 的 “9 Nc3 is best, but still losing: 9 ... Re8 10 Kf2 (or 10 Qd2 Qxd4! ...” 被拆成 “9”、“is best, but still losing: 9 ...”、“10”、“(or 10”，全部挂在 Nc3 后。用户红圈就是这些真实产物，不是浏览器凭空乱码。
4. **注释协议的信息没有完整落实。** SourceNote 已允许多 source_refs 和 before/after；compile_relations 按每个 fragment/gap 单独生成文本，用首个匹配 note 的同一锚点；source_compiler 又把所有 annotation relation 固定为 after。同一段的后行若不在模型 note.source_refs 中，就落到顶层正文。前端每个 annotation 单独一行并统一斜体，使碎片进一步打断棋谱。

## 5. 修复设计

### 5.1 稳定棋局身份，区分两种续接边界

保留“模型声明来源关系 → 程序编译/验证 → 人工审核”的总体架构，修改内部关系协议，不重做 PDF/OCR/Jobs 系统。

- 输入中由程序分配既有棋局身份与线路身份；前驱节点锚点属于哪局是已知事实。外部锚点仅供进入前任务已有局面；本任务后续窗口继续引用 prior_structure 中的同局节点。
- 模型创建新 game 只用于真正独立例局/理论起局。临时增量组不要再伪装成新棋局身份；编译器可内部保留从多个外部入口编译的片段组。
- 第二窗口所需关系应是 game_ref=game2-cont、line_ref=g2-main、continue after t50_18_7；模型继续负责来源语义中的“接哪一条线路”，程序负责据引用确定同局和父节点。
- 对旧响应，允许通过**相同前驱包、同一前驱 sequence 和显式父来源引用**证明局身份别名。不能仅因 FEN 相同、SAN 相同或某局面可走而合并。
- 修复应一次处理入口及其依赖组的 game_ref/line_ref/entry。若 parent 引用已经唯一确定同局，可由程序传播身份；有多个来源线路候选时才局部补问。
- 阅读范围仍保留连续前后文；输出分窗不必完全取消。此次问题不是缺少全文。后续可去除已结束旧局的大量无关锚点并压缩重复样式，但不以减少前文替代身份修复。

### 5.2 失败棋谱保留为可重放的依赖组

- 段内失效不删除其“棋谱候选”性质。保存 root、segment IDs、token/source refs、声明关系及依赖，审核显示一张“15.Kd1 入口未确定，影响 57 个候选”卡。
- 复用已保存 semantic_manifest，不另建任务调度框架；必要的 blocked group 标识可随现有 unresolved.extensions/诊断保存。可播放的 CCEF 仍只包含合法节点。
- 修入口后重放该组，自动去重用户 manual-1，并锁定人工 UCI/父节点/NAG。预览新增 55 个合法节点、1 处计划处理；确认后保存新审核修订，既有撤销继续可用。
- 文档恢复加载各已提交 segment 的 manifest、前驱快照与来源映射。用来源出现匹配审核节点，不能依赖 p48s1n61 等重命名后的临时 ID；从当前人工约束重算受影响的页段，不把已审核的前段整体替换。
- 增加简单的“已编译棋步 / 阻塞棋步候选 / 说明或计划 / 未判定来源”计数。显示“1 组影响 57 招”，不要用片段出现率和删除后的合法率掩盖损失。不同于严格要求每个 SAN 词法候选都必须是走子。
- 当前按钮在 document 后端未支持时不能暗示可用；交付该切片时同步接通真实文档路径。

### 5.3 用完整讲解段保存注释，不以“扣掉棋步后的碎屑”定义正文

保留 PDF 原始行、字符偏移、样式与哈希作为证据；在其上建立轻量段落分组：

- 按同栏、相邻行距、缩进、句法连续、标题/独立棋谱/图示边界合并软换行。跨页合并必须有延续证据；不能无条件把同页文本粘成一段。
- 独立棋谱行生成棋步；回合号、点号、NAG 与对应走子一起算已消费的记谱范围，不再生成单独正文。结果比分、实质数字不使用全局“删数字”处理。
- 混合讲解段保留**完整句子，包括其中提到的棋步**，并独立生成它包含的真实变化。比如保留完整的 “9 Nc3 is best ...” 作为一段注释，而不是挖空 Nc3/Re8/Kf2 后拼残句。重复记谱是讲解的必要内容，默认折叠可控制空间。
- SourceNote 多 source_refs 编成一个 text/evidence[]，保留 before/after；优先使用明确来源锚点。段落内涉及多个分支时允许整段挂在变化入口，不强求逐短句精确挂接。
- 未判明锚点的完整讲解段可以属于本局的“未定位讲解”，不强行最近合法节点挂接，也不阻断棋谱修复。
- 可先复用 SequenceAnnotation.text、anchor、evidence[]，不必一开始建设完整富文本 AST。只有确实需要句中可点棋步时，再添加来源 move_ref 链接。
- 旧结果从已保存证据与 note 响应重建段落预览，人工修改过的正文优先保留；不直接拼接所有当前碎片，也不让模型重新改写整本正文。

### 5.4 审核默认以修棋谱为中心

- 默认“紧凑棋谱”模式：同一锚点的一段讲解显示为一行摘要/展开入口；展开才显示完整文字。另提供“显示完整讲解”切换。
- 页码和编辑控件跟随整段，点击/悬停展开；数字碎片应在编译层消失，不能仅 CSS 隐藏。
- 未挂接正文按局/小节收在可折叠区域，避免每个物理行都插在棋谱之间；blocked 棋谱问题保持显眼，不随普通注释一起隐藏。
- 任何来源片段（含已误判 prose）都能选择文字“转为棋步”，复用目标棋步点击、接后/替代、SAN/棋盘预览。修复原段的部分内容时按字符范围保存剩余文字，不能把整段正文都删掉。
- 模型已声明的整组棋步优先“修入口 → 恢复组”，不要求用户对 57 招逐个转录。
- 继续共用已有棋谱树排版；注释密度只影响呈现，不改变棋步父子关系、节点 ID、拖选发布和人工挂载语义。

## 6. 推荐交付顺序与适量验收

1. **先补齐增量跨输出窗口及文档恢复。** 用这两个真实任务的保存响应重放；人工 v2 的 Kd1 必须原样保留、去重，恢复另外 55 个合法节点；31...Ne2+ 保留计划或一项局部疑点。棋局 2 主线到 36...Qc1+；前段 142 个原节点与原追加 84 个有效节点关系不变。不能以“0 非法”代替主线/来源完整性验收。
2. **保留阻塞棋谱组并开放误判文本转换。** 真实未修响应应展示 1 个根问题及其影响规模；在文档审核上只修入口后可预览组恢复、确认、撤销。可复用本例，不制造随机错误或再付费制造失败。
3. **段落编译与紧凑讲解展示。** 用 p44 的混合变化段、p50 的两行说明与独立谱行、p51 的两行 Nh3 讲解验收：句子完整；没有独立“11 .../12/13”行；before/after 保留；讲解折叠不隐藏未解决棋谱；拖选和重新挂接照常。
4. **最后才验证新的模型输入。** 编译器/审核改动重放旧响应即可。身份协议/提示词修改后才考虑一次限定页段的真实 DeepSeek 提取，检查新输出不再重复创建同一续局身份。新调用须遵守有效的外发范围与剩余预算，不默认重跑整个六书集。

本次不要求新增数据库层、通用工作流框架或多轮模型检查链。涉及主要文件：
extraction/relations.py、chunks.py、source_compiler.py、score.py；
services/pdf_review_recovery.py、pdf_review_ledger.py、必要的文档来源映射；
review 的既有编辑/恢复操作；
frontend/src/app/PdfReviewPage.tsx、reviewMoveLayout.ts。
段落分组宜是简单的来源辅助模块，避免继续把所有功能堆进 relations.py。

前一次“三个增量切点通过”的结论仍只适用于那些样本；本次真实任务揭示了“跨任务续局 + 一次追加内再次跨输出窗口 + 合并文档人工恢复”的未完成边界。不能将整个增量审核闭环标为验收通过。

## 7. 实施与真实 API 复验（2026-10-01）

交付范围：

1. v9 跨窗口复用 continuation 游戏身份；仅在来源明确步号/轮次且前驱主线候选唯一、合法时协调外部锚点。关系补丁按 owned source span 定位新增项，文档审核加载原追加页段、不可变前驱 CCEF 和人工修订，预览/确认可重放并保留人工节点。
