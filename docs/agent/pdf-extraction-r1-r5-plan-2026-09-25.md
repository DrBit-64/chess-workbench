## 2. 本轮确定的设计方向

默认流程：**自动观察排版 → 理解来源片段与例局 → 建立主线／图示起局 → 整段变例候选挂接 →
棋规与来源联合确认 → 分支级待审与可视化修复**。

1. 不让用户在提取前配置颜色、粗体等固定选项，不开发书籍模板编辑器或按书名的特判。
2. 保留 span/token 的字体、颜色和位置。系统从当前范围挑有棋谱和说明的代表页，形成简短、
   带来源例子的阅读提示；不是所有粗体都主线，也不是所有蓝色都一个层级的支线。
3. 阅读提示是可修正的线索，不能覆盖局部语义。第一次范围内做一次小型分析；已有提示可复用，
   实际遇到反例才局部更新。无须每页增加一次模型调用，也不建设通用自动学习／分类框架。
4. 模型明确选择来源组、线路、片段入口（延续／替代／分出）及来源锚点，必要时局部消歧；
   程序解析该选择并按确定规则连接，不独立猜作者所指的线路。程序解析记谱、维护作用域、
   验证棋规。主线/示例身份保存在来源结构中，不从“当前哪些节点合法、谁 sibling_order=0”反推。
5. 整段都合法仍不证明父节点正确。无法确定时保留原段和候选，禁止用最近同色合法节点强行消歧。
6. 用户纠正具体内容，例如“这里恢复主线”“这是独立示例”“这是计划”，不承担编写书籍规则的任务。
   先修改选定段落；相似位置只提供可预览的建议，不能自动改写全书或覆盖已批准结果。
7. 保留顺序 worker、来源工件、CCEF 审核接口与正式知识图。新内部协议需要版本时明确标记新结果并
   保留旧读取；不覆盖历史响应、审核基线或直接写入知识库。

### 模型调用策略如何落到开发步骤

下面四条是条件选择，不是每次必跑的四轮模型调用，也不新增R6等开发阶段：

| 情况 | 应做什么 | 所属步骤与可检查结果 |
| --- | --- | --- |
| 一个完整讲解段可以可靠处理 | 一次解释整段关系；程序复制原文并装配 | R3：Catalan p6–9先评估整段；记录实际输入、输出及来源父关系，不预设逐页调用 |
| 一次处理的输出负担或实测质量不合适 | 拆少数完整讲解段，尽量共用连续阅读范围 | R3：拆分理由可说明，前后语境保留、owned不重复；不要求固定页数/调用次数 |
| 少数入口仍有明确疑点 | 仅针对问题关系做有界补问，保留所需原文 | R3：正常路径不追加检查/修复调用；补问只更新问题段，无法判断则局部待审 |
| 保存响应已正确，程序装配错误 | 修程序后重放保存响应 | R1/R3：如Catalan b6→cxd5，不为纯编译器改动新增模型调用 |

这些规则针对关系解释；若使用了独立排版观察、局部补问或失败重试，也应计入实际总用量。
R5用网站新结果验收完整流程；旧响应重放只能证明对应程序修正，不能代替新协议或新输入的实跑。
缓存是成本优化项，无命中率硬门槛；不因此删除必要原文或再建一套全局测试框架。

## 3. 开发顺序和每步验收

### R1 — 修正会扩大错误的本地改挂

**交付：** 修父节点后立即刷新受影响局面，连续变例的子节点不再因过期状态被移到别的分支。

**实施范围：** `extraction/source_compiler.py`，必要时相关 `chunks.py` 调用接缝与聚焦测试。
先为以下两处从原 PDF 写出目标父关系，再离线重放。只标当前 bug 所需片段，不先全量标注。

**通过条件：**

- Catalan p7：`7.cxd5` 跟在这条变化的 `6...b6` 后，不能被本地修复改接 `6...c6`；
  后续 `...Bb7` 按本段来源解释，不靠删节点消除错误。
- Magnus p139：`9.Qxc4` 跟在对应的 `8...dxc4` 后，不能落入 `7...Nbd7 8.cxd5 cxd5` 变化。
- 修复父节点后，后代使用更新后的棋盘与验证状态。存在多个来源上无法区分的候选时，局部待审，
  不以距离或单步合法做最终裁决；不得破坏已确定的连续片段。
- 保存前后父关系与原页位置对照，并添加一个覆盖此类过期局面 bug 的关键回归；
  不要求此时两本所有错误清零，也不能用合法总数增加代替上述关系正确。

**最小验证：** 编辑时运行新增回归；切片完成跑 source compiler/chunks owning tests，
两本保存响应各做一次离线核对。现有测试若固化了错误来源关系，以原页说明并修正预期，不静默弱化断言。

### R2 — 保留细粒度样式，自动形成阅读提示与主线预览

**交付：** 无需填写格式配置就能查看系统识别的实战主线片段、示例和说明，点击可回到来源。
这一步交付来源角色／主线顺序的预览，完整棋规装配和嵌套分支验收归 R3。

**实施范围：** `extraction/{pdfium,evidence,draft,interpretation}.py`，必要的来源读取与
`PdfSourcePage.tsx` 预览；阅读提示优先复用现有 semantic manifest，不先新增独立配置表或引擎。
需要改公开 schema 时连同生成契约更新。

**通过条件：**

- Catalan p6 同一行黑色 `5.Bg2 O-O 6.O-O` 与蓝色 `6.Nbd2` 保留不同 span 的颜色与准确来源。
- Magnus p140 正文中的 Bf5 与独立粗体主谱中的 Bf5 可区分；Question/Answer 粗体标签不被当棋步。
- 同一正文块允许混合说明、主谱和多层变化；无法由样式判定时保留语义判断空间。
- 两本无需书名分支或用户配置即可产出可检查的阅读提示，附实际来源例子。按原 PDF 对照主线
  片段顺序与示例边界，不能把 Catalan 蓝色完整示例当作黑色实战主谱。
- 发现局部格式反例时允许局部判断不同于提示；旧证据没有字体时仍可读取并保留原文。
  图区的棋子字形不再作为普通正文交给角色识别。

**最小验证：** 混色行／粗体的聚焦 renderer 回归，目标原页与角色预览人工对照；
解释器接口变化使用一个保存响应或 fixture 验证传递，不为样式字段做组合穷举。
实际读取 PDF 即可获得的样式不另开 OCR／视觉模型项目。

### R3 — 建立主线与分支作用域，按整段变化挂接

具体模型 JSON、入口公式、启动上下文与失败处理见
[关系协议草案](pdf-extraction-relation-protocol-2026-09-26.md)。不可将“程序找候选”实现成全图合法位置搜索，
也不可只换模型输出格式、随后继续运行旧的自由改挂链。

**交付：** 两个完整页段产生来源关系正确的实战主线与变例；局部疑点集中显示在分支根部，
一次上游修正能带动相关后代重新计算。

**实施范围：** `extraction/{interpretation,chunks,source_compiler,score}.py` 与相应 service 接入。
必要时抽一个清晰的小型关系解析模块，不建立通用修复工作流。将 R1 局部修复逐渐纳入统一装配，
避免新增一轮彼此覆盖的启发式。

**通过条件：**

- 模型输出来源片段和明确入口；程序按root/continue/alternative_to/branch_after装配。
  用来源对照验证替代、恢复、嵌套和同名着法，并包含错误挂接仍合法的案例；新关系不再经过
  旧的自由改挂链覆盖。首次主线仍由模型解释，不假定程序已经知道正确主线。
- 为两本原页逐步补齐完整实战主线和变例根／范围标注；标注来自原页而非当前提取结果。
  本步骤完成时，两段主线的着法、顺序、父关系与原文一致；每个已标注的明确分支根归属正确。
- Catalan：黑色 `1.d4 d5 ...` 保持实战身份，蓝色不同走法次序保持独立来源；p7 b6 变化正确，
  p8 不同变化中的同名 `12...Rc8` 不误并；连写 `18.Bxg5 Qxg5` 不漏失。
- Magnus：p140 主谱 `9...Bf5` 接实战 `9.Bf4`，不能接 Nc3/Rd1 示例；p145 `24...Rf6`
  接 `24.Bh6`；直到 p149 的主线都使用所属例局的上下文，不沿用停滞的旧分支。
- 阅读范围与输出范围分开：模型默认看到预算内本局/本节连续正文，含前后文、标题及恢复段；
  只输出 owned 范围。长范围必要时用连续重叠窗口，不能只传程序挑选的稀疏证据或每页正文。
  在保存请求上核对实际原文范围；以相同样式、输出协议和编译器做已知挂接点的窄/宽上下文
  有界对照，记录来源父关系和用量，不以增大配置上限代替可见输入或正确性证据。
- 不默认逐页调用：先合并可处理的完整解释段。多次调用时固定原文/token前缀，将本次结构与
  owned范围后置；使用同一阅读范围时来源ID/顺序稳定。检查实际请求前缀，不凭正文重复率猜缓存。
  记录供应商已提供的cache hit/miss、输出/推理tokens及耗时（必要时触及provider/deepseek适配，
  复用现有工件）；含初次/失败调用一起比较成本，不专门付费预热或建设通用缓存/监控系统。
- 从保存的调用轨迹确认：无疑点不自动追加关系复核/修复轮；补问仅处理具体疑点，不能重生成
  全段覆盖已正确部分。纯程序改动可离线重放；输入/协议改变后的新语义结果另做有界实跑确认。
- 跨块携带当前例局、来源主线进度和未结束分支，不再由最近16个合法棋步定义全部上下文。
  已知关系但棋规暂未解决时保留依赖身份；有独立可信起点的后段仍可处理。
- `Nb1-c3`、缺少应招的威胁等保留为计划／注释；有完整应招的正文变化正常提取。
  重复提及不是重复执行；同 SAN 不同来源／不同父局面不能随意合并。
- 起点支持标准局面、已确认图示 FEN 和已验证前驱；中途图不重开棋局。
  用现有英文 Endgame 图示起局样本做聚焦对照，不恢复中文书评估范围。
- 无法确定的一段保留原文、页码、候选与受影响后代。下游显示等待上游解决，不拆成几十个必须
  逐步处理的任务；其他分支仍可浏览。不得通过大量降为 prose/unresolved 或删除内容来宣称通过。

**最小验证：** 编译／跨块关键回归、两本完整页段来源对照、一次图示起局复核。
优先保存响应；新结构必须重新解释时只对受影响选定页调用，并单独记录请求、版本和用量。
聚焦回归过后继续交付，不对所有历史样本每次重跑。

### R4 — 无 ID 的审核操作、整段拖动与撤销／恢复

**交付：** 用户在网页里选择并修复分支，不需要查找或输入内部 ID；能够撤销与恢复。

**实施范围：** `frontend/src/app/{PdfReviewPage,reviewMoveLayout}`、`review/editing.py`、
review schema/service/API 及已有修订记录。拖动与点击选择共用语义操作。

**通过条件：**

- 用户通过页码、回合、着法、分支名称和棋盘选择目标；改挂、注释锚点、待审片段归属均不要求输入 ID。
- 拖动整段变化，明确显示“接在此步之后”或“作为此步的并列变化”；保存前可预览棋盘、影响范围
  和剩余问题。原文、注释、子变化随段保留，后端重新验证。
- 支持同序列改挂，也能把误拆到另一序列的同一例局片段转移／合并；不把拖动仅包装成现有同序列 API。
- “这里恢复主线／这是独立示例／这是计划”等纠错作用于选定内容；不得未经用户操作批量改全书。
- 完成一次真实分支的“改挂→撤销→恢复”：棋盘、父关系、注释、来源一致。撤销／恢复产生新修订，
  保留历史；新编辑截断当前 redo 路径；刷新页面后保留当前结果；不撤销已发布知识数据。
- 来源阅读顺序和分支拓扑能分别查看，选择联动；非法／待审分支仍可定位原文。

**最小验证：** 一条主要网页交互流程加一条修订持久化集成验证，覆盖实际改变的关键不变量；
按需复用 editing/ledger/API 测试，不建设拖动方式、数据库方言的组合矩阵。
可以提前做目标选择器原型，但最终拖动／跨序列验收应使用 R3 稳定后的关系表达。

### R5 — 新实跑与整体验收，再收尾 P6

**交付：** 当前两本在正常网站入口直接可用，质量报告包含来源依据和实际人工修复成本。

**执行与通过条件：**

1. 先冻结两本的来源标注和统计分母。用新实现从网站各完整提取一次；不人工修改模型响应、拼接
   多次好片段或重试到抽到满意结果。保留实际请求／响应及结果身份。
   报告总调用次数、各次用途/阅读与owned范围、耗时、供应商已提供的cache hit/miss及输出/推理
   用量和估算费用；包含首次、排版观察、补问及失败/重试，缺字段注明未提供。不以缓存高命中
   抵消关系错误，也不以无命中直接判提取质量不合格；是否继续拆分由来源质量和实际负担决定。
2. 核对完整主线、已标注的关键变例根／范围、漏失棋步及计划引用；运行成功和合法率单独报告。
   操作者接受一次提取中约 1–3 条局部棋谱分支或注释挂载错误，只要它们可定位、可在审核页修复，
   且没有大段串线、整局/主线丢失或重复节点误并。局部 oracle 逐项报告通过/失败，不能因整体可用
   就把明确的错挂改记为通过，也不因一处小错宣称整段不可用。
3. 对真正的来源歧义列出逐项依据、范围和处理动作；“算法还不会解析”不能冒充原文不明确。
   记录待审分支数和人工操作数，不能用降级大量片段换取成功。图示不确定、文字疑点可以局部保留；
   明确主谱/变化上的少数可审小错按上项容差记录，成批静默错误仍不通过。细小文案或非关键展示问题
   单列，不阻塞整个阶段。修复必须从失败来源提炼可复用的结构/证据规则，不按书名、页码或单个局面特判。
4. 两本首次新实跑均通过后，各做一次受控重复检查，确认不是保存响应特选组合的偶然结果。
   这是本轮收尾检查，不是每次编辑的门槛，也不是统计稳定性的证明；若失败，报告并定位，不能隐去。
5. 用网页完成至少一个真实待审段的可视化修复与撤销／恢复。没有真实歧义时可在独立审核草稿中
   构造一次可逆误挂来验证交互，不修改原始基线或正式知识。
