# PDF 有限并发：实现与验收记录

日期：2026-10-03。对应 [ADR 0027](../decisions/0027-bounded-async-pdf-extraction.md) 与 [C1–C4 计划](pdf-concurrency-plan-2026-10-03.md)。代码未提交；正式网站中的候选均未批准或发布。

## 实现

- C1：应用持有一个提取运行时；PDFium 全部经一条专用线程渲染；页证据、棋盘识别、输入构造、响应折叠及编译进入串行本地阶段。v9 聚合文件在 SQL head 事务外准备；提交时复核版本、审核快照、工作者租约和领取轮次。Stockfish 保留独立工作者。
- C2：主生成和局部补问共用每运行、每批次的完整响应检查点。索引绑定来源哈希、前驱快照、流水线、完整请求及模型配置；跨领取轮次重放，输入变动不命中。已接收但未落盘的网络结果仍可能在重试时再次收费，无法提供外部 exactly-once 保证。
- C3：同一进程中默认两个 PDF 工作者、两个共享模型名额、本地阶段一个。HTTP 总时限从拿到名额后开始；不同任务的 HTTP 等待可重叠，每任务仍按来源顺序折叠。正式结果登记检查当前执行者和取消状态。一个完整段因模型推理额度耗尽时，只拆分该段的输出归属，保持全文阅读输入；聚焦模拟测试覆盖此路径。
- C4：经网站正常 `POST /api/pdf-extractions` 在日常数据库启动三个 Endgame 页段；失败页段经通用修复后重新提交。三个最终候选均在 Sources 可打开，保留原页、棋盘和两局各自棋谱。

关键代码：`api/app.py`、`config.py`、`services/extraction_runtime.py`、`extraction_checkpoints.py`、`pdf_render.py`、`pdf_extraction.py`、`pdf_source_extraction.py`、`pdf_incremental_extraction.py`、`pdf_documents.py`、`pdf_source_read.py`、`extraction/chunks.py`、`extraction/diagram_context.py`。没有新框架、迁移或 API 合同变更。
