# 审核修入口后的依赖恢复（2026-09-27）

本轮已将之前的只读程序试验接入 v8 审核页。用户先在棋谱中改挂一个来源明确的棋步，再点「根据人工修正恢复后续」；服务读取本次提取保存的来源关系响应，在内存中把人工改挂转换为一个来源关系补丁，重新编译后续合法棋步，再与当前审核修订合并。页面先显示候选和新增/解决/冲突数量，可在原稿与候选间切换；只有「确认恢复」才按当前版本和候选哈希追加一版审核修订，现有撤销/恢复可用。全程不调用模型，也不直接改写提取原件或已发布内容。

合并以来源引用及完整 UCI 父链匹配已有棋步；人工新增棋步、评价符号和文字修改留在当前修订。新候选如与人工内容冲突，保留人工版本并在预览中列出冲突。旧待审卡仅在对应来源棋步已被恢复且候选中不再存在该处问题时才移除。前提是人工改挂的原棋步和目标棋步都能映射到保存的来源 token，且目标是已解释线路的末端；任意新录棋步、改起始局面、跨棋局重建或剩余独立语义错判仍需要另行处理。不能把局面合法等同于整局语义正确。

## 真实样本与人工模拟

选用 Catalan p6–9：第 6 页以 Naiditsch–Kopylov（Basel 2016，1–0）开始，第 9 页以 `31.Bxf8 1-0` 结束，下一局从第 10 页开始。这是不同于当前人工修订的 p10–17 的完整棋局范围。复用该任务保存的 v8 模型响应，不产生新费用。只在只读脚本中将一个来源主线入口错误接进另一合法变化，模拟「合法但挂错，后续断开」；再用正式审核编辑函数模拟一次人工改挂，并增加人工棋步、NAG 和正文修改。结果：错误候选 26 招，人工改挂后 27 招，程序恢复后 149 招（148 条原始来源棋步加一条人工新增）；新增 122 招，解决 43 条待审，冲突 0。148/148 原始棋步的来源出现及完整父链与注入错误前的已保存响应编译结果一致；138/138 原始主线着法仍是主线；人工棋步、NAG 和正文均保留。这验证了依赖恢复与人工编辑保留，不把原响应本身当成逐招人工标注的语义金标准。可重跑：`uv run --project backend --locked python scripts/check_pdf_review_recovery_catalan.py`；机器可读结果在 `data/debug/review-recovery-20260927/catalan-p6-9/report.json`。

对用户现有 Catalan p10–17 审核会话 v15 做**只读**真实预览：新增 38 招，解决 11 条待审，保留 48 招人工补录，候选共 141 招，合并冲突 0。该页段仍有其他独立关系错误，不能把这次预览宣称为整局修好；没有写入用户的 SQL 审核会话。
