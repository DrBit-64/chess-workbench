# PDF 审核恢复：真实 Catalan 下一局验收（2026-09-27）

本轮使用 Catalan 棋书 p18–24 的完整 Giri–Topalov 例局。原 v8 提取任务 `bf7260c9-35a1-51b4-9a20-96610a13caab` 是实际 DeepSeek 输出；没有由 agent 注入或篡改错误。任务与请求/响应保存在隔离目录 `data/debug/review-recovery-20260927/next-game-p18-24/`，不写用户现有审核会话。该局的模型提取用了 5 次调用、260951 输入 token、11672 输出 token；此后恢复试验只重放保存的响应，没有再付费调用。

## 真实故障与一次人工操作

原任务只有 25 个合法棋步、272 张待审卡。模型在后续输出窗口重新领取了只读前文，编译器因此把整批新页段当作越界；通用的只读前缀锚点修正后，保存响应可重放出 54 个合法棋步，主线在 `25...Rd7` 截止，仍有 96 张待审卡。后续真实模型关系还把蓝色 `25...Bxd6 26.Rxd6` 插入主线，错过黑色主线 `26.Nc4`，并把第 21 页的重复示例 `30.Rc1` 当作主线续谱。

模拟的**唯一人工操作**是用正式 `PdfReviewAddLine` 审核编辑请求，在已有 `25...Rd7` 后补入书中 `26.Nc4`（UCI `d6c4`）。程序从这一步的唯一来源 token 建立约束，拆开同一模型片段里的替代变化，重放保存的来源关系。模型漏掉的正文续谱则使用本局已确认主线的加粗文字样式作为局部线索：只有同一局内存在足够稳定的主线样式与明显不同的变化样式时，才按来源顺序、印刷步号、行棋方和 python-chess 合法性接续；异样式记谱按已确认主线相应回合建立候选变化。算法没有 Catalan 书名、页码或黑/蓝色常量。大量已有人工作业的会话仍使用显式关系重放，避免覆盖人工结构。

## 验收结果与边界

离线程序恢复到 **196 个合法来源棋步**、**111 个半回合的完整实战主线**，其中 141 个棋步来自程序恢复；93 张陈旧待审卡被移除，剩下 3 张。将第 26 步至最后 `56.Kd4` 的 **61 个半回合**与 PDF 独立誊录的主线逐招比较，全部匹配。另独立核对 **19 处变化入口**的确切来源父节点，全部匹配；包括修正点前后的变化，未以“棋步合法”冒充父子关系正确。模拟人工增加的节点保持原 ID，冲突为 0。

剩余三张待审卡是 p18 的 `Bf4`、p20 的 `Qd7` 和 p23 正文中的 `Rxb5 Bd2` 重复引述；仍需人看来源决定保留为变化或注释。只读预览用户现有 Catalan p10–17 会话 v24 仍得到原有的 3 处入口校正、42 个新增棋步、14 张解决卡、0 冲突；该会话的独立第 19 步语义错误仍未因本轮验收而宣称解决。
