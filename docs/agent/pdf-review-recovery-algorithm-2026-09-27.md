# 人工约束恢复算法：设计与实现边界

本文是 v24 诊断后的设计依据。稀疏人工入口、来源关系重放和局内版式续谱现已实现，真实下一局结果见[验收记录](pdf-review-recovery-real-acceptance-2026-09-27.md)。本文中“应”描述的更完整多轮字段级约束、自动移动已有机器节点、独立语义疑点检测仍属未完成范围；不能把这次样本通过等同于下面全部目标均已实现。

## 1. 输入分别是什么

### 原模型请求中的来源证据 D

- `source_spans`：连续正文、页码、块顺序、字符范围、bbox、文字来源、字符级颜色/粗体等样式。用于找回原文和来源出现、复制注释、核查布局；纯程序重放不会凭自然语言自行理解作者意图。
- `move_tokens`：来源 token ID、所在 span、字符范围、原始 SAN、可读出的印刷步号和行棋方。token 是候选词法出现，不能直接认定每个 token 都是实际棋步。
- `seeds`：标准起局或图示候选 FEN。起局需要经过既有确认/棋规边界；模型提出的图示解释不是自动真值。
- `window`：owned 与只读 context 范围，防止重复领取或把纯上下文当新增输出。
- `reading_hints` 是可修正的观察；`prior_structure` 是旧推断。两者均不得覆盖人工修订，尤其不能把旧 prior_structure 当成当前已确认图。

这些来源信息和原请求都已保存；无需再次读整本 PDF 或付费重新提取。

### 原模型响应 R

`games` 给出例局及起点，`segments` 给出每段的 game/line、入口和内部棋步序列，`notes` 给出注释来源/锚点，`unresolved` 给出尚不确定的来源/候选。还要重放该运行实际采纳的补丁，并保留“提议”身份。未装配成功的 segment 也必须保留，不能只从最终合法 CCEF 反推恢复材料。

段内后继和跨段入口是自动恢复的主要已有信息。完整正文或样式本身不能替代这些语义关系。

### 人工有效修订 H 与当前审核稿 V

读取审核命令及对应前后修订，明确哪些字段是人工操作，不能只比较首版和最新版。有效历史遵循现有撤销/恢复分支；同一事实以后续仍生效的显式修改为准。一次“确认恢复”保存的机器候选不能把全部后代自动升级成用户逐招确认。

- 改挂：确认源棋步的父来源出现，并保留被移动分支内尚未另改的关系。
- 设为主线：确认用户所选路径的主线优先级；同父节点的旧主线相应成为变化，不推断未知后续全部为主线。
- 待审转棋步：确认所选片段中的实际棋步、次序、入口及所属例局；将解析后的每招尽量对齐到该片段的来源 token。
- 人工文字、评价及注释锚点：保留各自被修改字段，不因改一个 NAG 就锁死该节点所有自动关系。
- 人工改起局：若该操作被本切片纳入支持范围，作为该局显式起点覆盖；否则明确报告不能重放，不能静默忽略。

多招人工录入不能把一个大段 evidence 当作每招的精确来源。用选中片段、记谱顺序、步号和从指定父局面解析出的 UCI 进行有序对齐；重复引述或多个匹配无法消歧时保留人工线路，只阻止依赖该不明来源对应的自动续接。用户自由增加的分析棋步可保留 review 身份，不伪装成 PDF 中的来源出现。

## 2. 来源约束与来源依赖

内部区分来源身份（运行、页、片段摘要、字符范围）和界面节点 ID。自动恢复出的节点仍带原来源身份，下一轮可以继续作为人工锚点。恢复使用两个独立属性：`parent(move)` 与线路中的首选后继 `main_child(parent)`；棋步主次和父节点都不能被另一个属性隐含替代。

示意（不是已冻结 API）：

```text
parent(t13_14_5 /* Nh5 */) = t12_52_3 /* e4 */       [人工 v20]
main_child(t12_52_3) = t13_14_5                     [人工 v21]
parent(t13_28_3 /* Be3 */) = t13_14_5               [人工 v22]
```

从每个旧 segment 建立来源依赖表达式：

- root：首招依赖该例局起点。
- continue(X) / branch_after(X)：首招父节点是来源 X；两者的线路身份不同。
- alternative_to(X)：首招父节点是 X 的父节点，并且属于替代 X 的变化。
- 段内 `[a,b,c]`：`parent(b)=a`，`parent(c)=b`。

先将全部已保存关系作为提议建索引，即使入口未成功编译，也保留其依赖。人工约束覆盖同字段的旧提议；若落在段中则在该处拆段。受影响的线路角色和替代关系应一起重算，不能仅改一条父指针却沿用旧 line-tail 状态。两个不相容的模型提议、缺少来源或来源重复等问题留作局部待审，不按“哪个局面能走”选父节点。

## 3. 编译、合并与重复恢复

将人工明确的父关系、主线优先级和起点应用到来源提议，再依赖次序装配，逐招以 python-chess 检查新的父局面、SAN/UCI、可用的印刷步号。合法性能够拒绝某种连接，不能证明连接符合作者意图。尚未确定入口的整组后继作为一个依赖问题呈现，独立线路可以继续恢复。

首次实现可顺序重编译整个选定页段的几百招，无需建设增量调度框架。概念上的影响范围仍需明确，以判断哪些自动关系可更新、哪些人工字段必须保留。

合并使用来源出现匹配已有节点，允许受影响的自动节点重建或移动，保留人工明确的关系和内容。父关系、主线角色、棋步正文、NAG、注释分别保护；冲突需展示，不能用同一来源再建一个副本绕过人工约束。新增来源映射与约束可依托现有审核修订/事件保存，不需要另一个审核数据库。

预览列出采用的人工事实、新增/移动/变更主线、解决的待审项、冲突和仍需判断的入口。确认仍按版本和候选哈希保存一版可撤销修订。下一轮从全部仍有效的人工事实重建，不能回到只遍历 v1。

## 4. Catalan 的具体边界

人工确认 `Nh5` 接 `e4` 且是主线，`Be3` 接 `Nh5` 后，旧响应已提供 `Be3 Nhf6 h3 b5 bxc4 bxc4 Rab1 Qa5` 的段内次序及 `Bd2 Qa3` 的后续入口，程序据此能重建到 `18...Qa3`。这些后续招法不需要用户再次录入。

`19.Re1` 在旧响应中错误地作为 `19.Bf4` 的替代，父节点成为支线 `18...Qc7`。人工对 `Nh5/Be3` 的修改没有告诉程序 `19.Re1` 应接实战 `18...Qa3`，两处又都合法，因此普通依赖重放不能保证自动识别这一独立语义错误。

此前诊断建议“展示第 19 步入口问题”是验收目标，不意味着现有结构检查足以发现它。需要增加有来源依据的疑点检测，例如与已确认主线的版式、步号、前后文位置不一致；这些只用于提示或补问，不将某种颜色硬编码为主线。对没有可靠证据的合法错挂仍不能保证零漏检。

遇到此类新判断，用户可再修一个入口，或另行使用小范围模型判断。后者读取完整连续原文、当前人工约束、当前线路和少量疑点，只返回入口父来源及线路角色/引用证据，不重新生成整局棋步。模型方案尚未实测，不属于纯程序恢复的已承诺能力。此前整局补丁调用失败，不能默认为每次恢复都增加该调用。

## 5. 下一实现验收

用真实 v20–v22 操作史（含 v16 自动恢复）验证人工新增、主线改变和恢复节点再改挂均进入约束；自动续到第 18 步，且不覆盖 v23–v24 已有人工节点。再模拟用户确认 `19.Re1` 入口，证明第二轮可推动其明确依赖。独立来源核对表只用于评分，不进入恢复输入。未采用的人工事实和独立语义问题必须如实显示；不得以所有招法合法、没有新增或单次首轮模拟通过代替多轮验收。
