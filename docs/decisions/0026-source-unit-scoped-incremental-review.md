## 3. 失败原因与实证

### 3.1 两个相同局面属于不同来源，模型选错了棋谱

本次模型输入含 191 个续接锚点：第二局例局 176 个，Theory 15 个；两者标题均未填入。第二局最后一页与 Theory 开头同为 p287，`_continuation_catalog` 因而同时提供了两棵棋谱的全部入口。

关键候选：

| 锚点 | 来源 | 对应局面 |
| --- | --- | --- |
| `anchor-208` | 第二局例局 p282 的支线 `5...Nxc6` | 与 Theory 起点完全相同 |
| `anchor-380` | Theory p287 的正式 `5...Nxc6` | 正确的续接来源出现 |

第一批模型明确输出 `g12-cont / seed_ref=anchor-208`。编译器验证 FEN 和棋步合法后，合并器按指定锚点挂入第二局。其余小节延续这个归属，最终污染整棵例局。程序没有在“来源所属内容”这个层面约束模型。

`_last_game_start` 也仅凭棋步证据的最后页选择前驱；同页结束／开始的两个内容无法由最大页码区分。增加“优先最新／主线／最近合法局面”只能碰巧修好此例，不能建立通用的归属规则。

### 3.2 A3 的模型输出并未丢失，但修复没有覆盖依赖

模型在 A2、A3 两批分别声明续接组，两者都引用同一个旧锚点 `anchor-210`。`canonicalize_continuation_games` 以锚点归并组名，而编译器每组只接受一个根，A3 新根与 A2 冲突。

补问随后正确地把 `seg-A3-main` 改为从 A 的 `6...Bf5` 分支，但 `apply_relation_patches` 只改该段的 `game_ref`，没有同步迁移六条依赖支线。它们仍属于 A2 的组，于是变成 12 个散落的待审来源片段。

**离线实证：**重放保存的 12 批响应和已接受补丁，完整复现 491 节点／13 待审；只在内存中同步这六段的归属，得到 **525 节点／1 待审**。没有新增模型调用，没有发明棋步，没有写回网站。整棵 Theory 的错误归属仍然存在，所以这不是最终修复或验收通过。

独立读原书得到的 A3 已核对部分如下，六条支线共 34 个半回合：

| 入口（在 A3 主线中） | 支线 |
| --- | --- |
| `7.Ne2` 后 | `e6 O-O Bd6 Bg5 O-O Nd2 Qc7` |
| `7...Qb6` 后 | `Bxc6+ Qxc6 Nbc3 e6 O-O Rd8 Be3 Be7 Qd2 h6` |
| `8.Nbc3` 后 | `e6 O-O Bd6` |
| `8...e5` 后 | `O-O O-O-O Bxc6 exd4` |
| `8...e5` 后 | `Bxc6+ bxc6 O-O O-O-O Na4 Qa6 c3 h5` |
| `15...O-O` 后 | `O-O-O Qd4` |

A3 主线 18 个半回合为 `Ne2 Qb6 Nbc3 e5 dxe5 Rd8 Bd2 Nd5 Nxd5 Rxd5 c4 Rxb5 cxb5 Nxe5 Nf4 Bd6 Qe2 O-O`。所有上述路径从 Theory 的 `6.f3 Bf5` 位置验证合法。这个 18+34 是已核对且模型明确输出的子集，不是对 A3 全文的完备覆盖声明。

### 3.3 两种普通记谱形式在程序入口被误读

- **p288 升变：**原书 `5...Bxd1?? 6.c7+! Nc6 7.cxd8Q+ Rxd8 8.Kxd1`。模型连升变的原文引用都返回了，但词法提取和 quote 回退都要求 `=Q`，拒绝 `cxd8Q+`。补问把整条真实可播放线路降为注释，六个棋步没有入谱。
- **p317 长易位：**原文黑方 `12...0-0-0` 在两行分别为 `0-` 与 `0-0`。逐来源块的词法提取只得到后者，按短易位处理。该局面短易位非法、长易位合法，随后八个棋步一起被丢下。正确线路是 `11.c4 Nb4 12.Na3 O-O-O 13.Be3 e5 14.dxe5 Nd3+ 15.Ke2 Bxa3 16.bxa3 Nxe5`。

这两处由直接查看原页确认，并用棋规核验正确写法及后续路径。不是应当让模型再猜一次的泛化问题。

### 3.4 覆盖指标与界面掩盖了缺口

manifest 的 `433/433 represented_fragments` 只表示原文在结果某处保留；变成注释也算覆盖。当前 665 个词法候选中，模型前 12 批明确声明了 539 个不同 token，其中 48 个未成为最终节点：A3 的 34 个、升变线其余 5 个、长易位及其后续 9 个。升变本身另是 quote 引用，未计入 665 个候选。

剩余未声明候选含目录、重复引用、计划等，不能直接认定都是漏谱，更不能用 491/665 充当准确率。

审核目录只检查标题首步在任意棋谱中的来源引用，并只跳转 PDF 页，不定位局部棋树。A3 的入口虽然存在，六条支线仍缺失；界面却没有提供对应小节的缺口概览。

### 3.5 已批准人工修订没有成为追加基线

此前文档修订 2 的两局为 188／175 个节点；已批准审核修订中的两局为 189／176。人工补入的 `Rac8`、`Bb8` 在新合并结果中既没有原节点，也没有同局面、同着法的替代节点。

`append` 绑定文档修订的哈希，后续加载该文件；这里没有使用已保存的审核修订。旧审核历史仍然存在，不是物理删除。但后续追加结果遗漏人工成果，会使用户重复劳动。这是独立于 Theory 归属的连续工作流缺陷。

## 4. 建议架构：先确定来源单元，再确定棋步入口

### 4.1 来源单元是轻量元数据，不是新的棋谱引擎

为每局例局、独立 Theory 或图示练习保留稳定 `scope_id`、标题、类型、开始／结束的来源跨度、对应棋谱 ID。边界精确到同页中的片段／偏移，不能只有页码。A/A1 等编号在该单元内命名，下一章的 A 不与上一章混用。

在现有读取／首批关系解释中确定边界：程序提供标题、结果标记、新起谱等来源证据；模型解释边界和所属内容；已确认的边界由程序保存并在后续批次复用。无须每页先额外调用一次分类模型。有明确 `Theory` 标题、新起谱及前局结束时可自动建立候选单元；矛盾只产生一个可见的归属问题。

本例前驱应记录：例局 12 已结束，Theory 自 p287 中部开始且仍在展开。追加 288–318 默认延续 Theory。例局正文可以作为只读比较材料，但其中的同 FEN 节点不再混进 Theory 的可挂接目录。

来源单元和 Position 图分离：同一个 FEN 可以对应多次来源出现；只有同一来源单元内明确引用的出现实例才能自动续接。跨单元引用可展示为引用关系，不默认把两棵来源棋谱合并。

### 4.2 模型与程序的职责、输入和输出

输入沿用连续原文／样式、来源 token、编号目录、此前结构，增加来源单元和明确限定的续接候选。例如：

```json
{
  "active_scope": {
    "id": "theory-elbow",
    "title": "Elbow Theory",
    "source_start": "p287:Theory标题来源",
    "sequence_ref": "existing-theory"
  },
  "attachable_anchors": [
    {"id": "theory-after-5-Nxc6", "scope_ref": "theory-elbow", "source": "p287:5...Nxc6"}
  ],
  "section": {"id": "elbow-A3", "label": "A3", "parent_ref": "elbow-A"}
}
```

示意输出（实际协议字段在实施时统一版本化，来源 ID 由程序提供）：

```json
{
  "scope_ref": "theory-elbow",
  "section_ref": "elbow-A3",
  "line_ref": "A3-main",
  "entry": {
    "kind": "branch_after",
    "target_line_ref": "A-main",
    "target_move_ref": "p288:6...Bf5的确切token"
  },
  "move_refs": ["p293:7.Ne2的token", "p293:7...Qb6的token"]
}
```

模型判断这段是哪个小节、从哪个来源棋步分支及何处恢复；程序提供并维护稳定身份，检查引用属于该单元、绑定来源出现、执行棋规并保存可审阅结果。不能把多个窗口临时命名的 game 直接当作稳定来源单元，也不能以相同 anchor 合并 game 身份后再遇到多个 root 冲突。

一个来源单元允许多个入口片段。入口锚点是连接位置，来源单元是所有者；二者不能互相代替。保持现有 `root/continue/alternative_to/branch_after` 语义，分离当前 `game_ref` 混合承担的所有者与续接组职责即可，不重写底层图结构。

读取范围继续提供当前完整讲解段、前后文和早期入口。输出按完整变化群有界分批；范围过长再拆分。精简无关例局的可挂接目录，不以缩短为“最近若干合法节点”换取成本降低。

### 4.3 保存人工成果，再启动追加

追加开始时固定一份不可变输入快照：文档修订、当前已保存审核修订（若存在）、哈希与来源单元注册表。模型上下文和最终合并都用同一快照，不能一个读人工修订、另一个仍与旧文档合并。

已批准的两处补步必须进入此快照；已保存但未批准的人工修改也保留其编辑状态，不能因追加而静默消失。运行中新产生的编辑用已有版本冲突机制提示处理，不建立自动三方合并框架。新提取内容仍待审核，原批准状态不能自动批准新增内容。

### 4.4 正规化来源记谱，并成组恢复依赖

- token 保留原文和精确来源；另提供规范记谱。支持无等号升变、跨行易位等通用格式。跨行 token 必须能指向多个来源跨度；只在排版邻接和记谱语法共同支持时拼合，不任意拼接两段文本。
- 单一入口／所有者变更，计算引用依赖闭包，把依赖的段、注释引用、编译绑定一起迁移并重放。同属 A3 不代表所有段均依赖同一个入口，按关系引用决定边界。
- 模型已声明而未编译的真实棋步保留为“受阻变化”，不是普通注释。对可播放线路的 demotion 不能作为自动提高通过率的修复；若确属计划，给出来源理由并作为可审阅分类。
- 修程序优先重放保存响应。只在来源语义尚不确定时对该问题群补问模型，并携带已确认归属及人工修改；不要默认全章重新提取。

保留现有局部失败机制；归属不确定时挂在来源单元的待审区，不污染旧例局，也不使整次提取失败。

## 5. 审核工作流

### 5.1 先选内容，再看局部棋树

沿用三栏：左侧 PDF，中间棋盘，右侧棋谱。增加内容／小节导航，不再把几百步和所有独立注释无差别堆在一个长列表里。

```text
内容：例局 11 | 例局 12 | Elbow Theory（本次追加）
Theory：A > A1 / A2 / A3；B；C；D > D1…D52

当前：A3 · 7.Ne2 · p293–295
入口：Theory → 6.f3 Bf5 → 7.Ne2
已声明棋步：52；已编译：18；受阻：34，属于 6 条变化
问题：修复入口归属未传递给依赖支线 [预览恢复这 6 条变化]
```

52 是已声明的已核对棋步数，不是全文覆盖率。另显示未解释的疑似棋谱来源群；标明尚未核对，不能给虚假的全节成功百分比。

点击 A3 同时定位 PDF 来源、棋盘入口和该节子树；祖先路径作上下文展示。支持“仅看本次新增”“仅看问题”“下一问题群”，仍可切回完整棋谱。重复／目录引用与棋步遗漏区别标记。注释默认折叠，展开时保留完整自然段及现有棋步覆盖标记。

### 5.2 状态必须帮助做判断

将单一“标题棋步已入谱”改为可分别查看：

1. **内容归属／入口**：所属 Theory 及入口路径；存在跨单元冲突时直接标红。
2. **棋步处理**：已声明并编译、受阻变化及影响数量。
3. **原文待核对**：未解释的疑似棋谱片段，目录／计划／重复引用可折叠；人工确认单独记录。

不声称程序能自动证明全书无漏谱。来源标题已经映射只是可定位证据，不能代替父节点和覆盖验收。指标在后端从当前审核修订与关系工件构造，前端只呈现，避免出现第二套判断算法。

### 5.3 一次修复一个原因，先预览再应用

本例应呈现三个可操作问题群，而不是要求手动移动 491 次或输入 34 个 SAN：

- **理论所属内容错误：**选择 `Elbow Theory`，预览将本次新增理论从例局 12 转入已有 Theory 棋谱。保留旧例局及人工修改。程序只迁移有确切本次来源与依赖关系的子树，不以“p288 之后所有东西”作为删改条件。
- **A3 依赖受阻：**同步父段归属后预览恢复 6 条变化／34 个棋步；若与人工修改冲突，只单列冲突部分。
- **记谱识别问题：**展示原页裁片和标准棋步，确认长易位或升变后连同后续恢复。用户无需填写 FEN、节点 ID 或 UCI。

人工操作沿用现有点击棋步选入口、整段恢复预览、审核版本、撤销机制。修复不自动发布。当前页面内的人工作业是对来源关系的约束，后续模型不能覆盖。

提取运行中也按来源单元／小节报告进度：已生成哪些小节、哪些入口待确认、哪些变化受阻。首版可从已保存批次生成只读进度，不要求边生成边编辑，也不新建通用任务引擎。
